# Screen spec — Screener

**Source of truth:** `CardStock Mockup/Cardstock Screener.dc.html` (881 lines, read in full 2026-08-10).
All line citations below are `Screener.dc.html:N` unless another file is named. Per `CLAUDE.md` §"Document authority",
this prototype is Tier 1: where `HANDOFF.md` / `DESIGN_NOTES.md` / `DISPLAY_VOCABULARY.md` disagree with it, the HTML wins.
Disagreements are recorded in §8 rather than reconciled.

Seeded values (12 cards, 6 screens, 3 backtest datasets) are **illustrative**. What is authoritative is the
structure, the state space, and the copy that is generated by code rather than seeded.

### Routes

**The HTML asserts no routes.** There is no `location`, hash, or history handling anywhere in the file; backtest is a
*state flag* (`state.bt`, `:427`) that swaps the results area, not a navigation. Routes are therefore doc-derived only,
and the docs disagree (see §8):

| Mode | Route (`HANDOFF.md:72`) | Spec (`CARDSTOCK_UI_SPEC_v1.md:112–113`) |
|---|---|---|
| List mode (no screen selected / default screen) | `/screener` | `/screener` |
| Saved screen | `/screener/{id}` | *(not listed)* |
| Backtest mode | `/screener/{id}/backtest` | `/screener/{screenId}/backtest` |

`HANDOFF.md:84` additionally assigns marketing `/screener` to `Cardstock Screener Landing.dc.html` — an unresolved
collision with the app route. Open question O-1.

### Purpose

A standing question asked of the whole corpus. The user composes AND-ed filter conditions ("chips") over a metric
vocabulary, names the resulting screen and gives it a one-line *thesis*, and sees the cards that match today. The same
saved screen can be replayed against history in **backtest mode**: every historical moment a card newly satisfied all
filters is treated as a buy signal, and outcomes are measured against a whole-corpus market index. The screen's
editorial posture is honesty about young data — every immature metric carries a caution, every unmeasurable horizon is
disabled with the date it matures, and the backtest window is bounded by an explicitly-explained "honest floor".

### 4.6 Backtest mode

Entering: `Backtest →` sets `bt:true, btPhase:'idle'` (`:601`). Leaving: `← Results` sets `bt:false` only —
`btPhase`, `btH`, `btExit` all persist (`:602`).

| Phase | Guard | Body | Trigger |
|---|---|---|---|
| Idle | `btPhase === 'idle'` (`:233`) | centred explainer, text differs per exit mode (`:620–622`) | entering backtest |
| Running | `btPhase === 'run'` (`:238`) | mono scan line: `scanning {months} months of history ({range}) · {measuring +{btH} outcomes… \| holding until signal exit…}` (`:625`) | `Run backtest` (`:624`) |
| Done | `btPhase === 'done'` (`:243`) | full results anatomy | **1100 ms** after Run (`:624`) |

The config card and the honest-floor banner are visible in **all three** phases (`:204–232`).
Changing horizon, exit mode, or screen while `done` re-renders results **immediately without re-running** — the phase
is never reset by anything except entering backtest mode.

### 4.7 Exit-rule states

| Mode | `btExit` | Horizon pills | Stat tiles | Entries columns | Histogram title |
|---|---|---|---|---|---|
| **horizon exit** (default) | `'horizon'` | live: `opacity 1`, `pointer-events:auto` (`:657`) | 6 or 8 (§4.8) | `+3M`/`+6M`/`+12M`, selected one tinted+bold | `{btH} return distribution` |
| **signal exit** | `'exit'` | **dimmed to 0.35 and inert** (`pointer-events:none`) but still laid out (`:217`, `:657`) | exactly 6 | `Exit return` / `Held` / `Status`, no tint | `Closed-trade return distribution` |

Group-level tooltip on the horizon block: horizon → *"How long each entry is held before selling, regardless of what
the screen says afterwards"*; signal-exit → *"Not used with signal exit — the screen decides when to sell"* (`:657`).

### 4.8 Stat tile sets (`btStats`, `:628–652`)

**Horizon exit** — 6 fixed tiles, plus 2 conditional:

| Tile key | Value | Sub | Colour |
|---|---|---|---|
| `Buy signals (entries)` | `ds.entries` | `ds.range` | ink |
| `Hit rate {btH}` | `stats.hit` or `—` | `stats.hitSub` or `no entries aged yet` | ink |
| `Median {btH}` | `stats.med` or `—` | `return per entry` | pos if starts `+`, else neg2; `mut3` when absent |
| `Mean {btH}` | `stats.mean` or `—` | `return per entry` | same rule |
| `Max drawdown` | **always `stats['3M'].dd`** (`:640`) | `screen equity` | neg2 |
| `Market index` | last index value vs 100 | `same window, buy & hold` | mut |
| `Best entry {btH}` | max non-null return in `rows` | card name | pos |
| `Worst entry {btH}` | min non-null return in `rows` | card name | neg2 |

Best/Worst appear **only when** `stats[btH]` exists *and* at least one seeded row has a non-null return at that horizon
(`:642–651`). So the tile count is 8 normally, 6 when the horizon has no aged data.

**Signal exit** — exactly 6 tiles, never more (`:628–634`):
`Buy signals (entries)` · `Hit rate` (sub `N of M closed trades`) · `Median return` (sub `per closed trade`) ·
`Median hold` (sub `entry to screen exit`) · `Open positions` (accent-coloured, sub `still match today`) · `Market index`.

Every tile has `cursor:help` and a `title` tooltip (`:286`); the eight horizon tooltips and six exit tooltips are
verbatim in `:629–649`.

### 4.9 Horizon maturity (disabled pills)

`btHs` builds one pill per `['3M','6M','12M']`; `off = !ds.stats[h]` (`:604–611`).

| Pill state | Styling | Tooltip |
|---|---|---|
| Selected, enabled | accent fill, card-coloured text | `Hold each entry {N} months, then sell regardless of what the screen says (currently selected)` |
| Unselected, enabled | card fill, muted text | same sentence without the parenthetical |
| Any pill, signal-exit mode | (block is dimmed/inert) | `Not used with signal exit — the screen decides when to sell` |
| **Disabled (immature)** | `hov` background, `mut3` text, border `#EBEBE7`, `cursor:not-allowed`, `disabled` attr (`:221`) | `No entries have aged {N} months yet — {maturity clause}` |

The maturity clause is the dataset's `ageNote[h]` with its leading `"No entries have aged … — "` stripped by regex
(`:608`), yielding e.g. **"the earliest cohort matures Sep 2026"** / **"…matures Mar 2027"** (`:507`).
Disabled styling **overrides** selection styling, so a horizon selected on one screen and immature on another renders
as plain disabled while remaining the active `btH`.

### 4.10 Missing-data states inside backtest

| State | Guard | Render |
|---|---|---|
| No aged entries at this horizon | `!stats[btH]` and horizon mode | story becomes *"We found N buy signals between {range}. None have aged {H} yet — {ageNote}"* (`:616`); hit/median/mean/best/worst read `—`; histogram card replaces bars with the age note (`:306–308`, `:660`); a grey age-note banner also appears below (`:311–313`, `:658`) |
| Concentration risk | `btPhase==='done' && ds.warn` (`:668`) | red banner, `⚠ CONCENTRATION` label + prose (`:314–316`) |
| Honest floor | always, in every phase | amber banner (`:232`) |
| Truncated entries list | `ds.more` / `ex.more` present (`:667`) | muted footer line inside the table (`:339–341`) |

### 4.11 Sufficiency exclusion (terminal only)

An amber strip is fused to the bottom of the table (`:380–385`), **always rendered**, containing
`{hiddenCount} cards hidden — insufficient data for {hiddenMetric}` (hard-coded `3` and
`churn (needs 60+ post-seam days)`, `:872`), a `show anyway →` button, and a `sufficiency rules ⓘ` link to
`Cardstock About Data.dc.html#sufficiency`. The binder view has no equivalent.

## 5. Interactions

### 5.1 Rail

| Control | Consequence |
|---|---|
| `«`/`»` toggle (`:81`) | Flips `railOpen`; glyph flips `« ⇄ »` (`:861`) |
| Screen row (`:57`) | `screen = id`, **and resets** `removed:{}`, `sortKey:'comp'`, `sortDir:-1` (`:711`). Does **not** reset `view`, `bt`, `btH`, `btExit`, or `btPhase` |
| ⋯ (`:61`) | Toggles that row's menu; `stopPropagation` so the document handler doesn't immediately close it (`:718`) |
| Rename (`:64`) | Closes menu, **switches to that screen**, enters name editing seeded with the current name (`:719`) |
| Edit thesis (`:65`) | Same, for thesis (`:720`) |
| Duplicate (`:66`) | Creates `{id}-copy{ms%1000}`, name + `" (copy)"`, same `sub`, `preset:false`, appends to `myIds`, switches to it (`:721–725`). Copies only the screen's **base** chips — user-added chips (`added[id]`) are not carried over |
| Delete (`:68`) | Removes id from `myIds`; if it was current, switches to `myIds[0]` of the remainder (`:726`). The `SCREENS` entry itself is not removed |
| `+ New screen` (`:73`) | Creates `new{ms%100000}` — name `Untitled screen`, sub `0 filters · just now`, thesis `click Edit thesis to say why this screen should work`, `chips:[]` — switches to it and opens name editing (`:851–855`) |

### 5.2 Inline name / thesis editing

Change updates `editVal` (`:706`); **Enter** blurs → commit (`:705`); **Escape** exits without saving (`:705`);
blur commits (`:697–704`). Commit writes into `edits[screen]` — a per-screen override merged over `SCREENS` at render
(`:694`). **An empty/whitespace value commits nothing** and silently keeps the previous text (`:702`).

### 5.3 `+ filter` — level 1 (metric list)

Groups render as uppercase headers with their items beneath (`:104–111`). Each item row is
`name · badge · ›` (`:107–109`). Clicking opens that metric's editor (`:789`). Only the five `LOW DATA` items carry a
hover tooltip; every other item's `title` is empty (`:786`). Every item is clickable — no metric is disabled.

### 5.4 `+ filter` — level 2 (editor)

| Control | Consequence |
|---|---|
| `‹` back (`:116`) | `editor = null` → returns to the list, popover stays open, nothing added |
| Window pill (`:127`) | Sets `edWin`; tooltip `Measure this metric over {window}` (`:819`) |
| Operator pill (`:137`) | Sets `edOp` to `≥` / `≤` / `between`. Tooltips: *"Keep cards at or above the value you set"* / *"…at or below…"* / *"Keep cards between two values — useful for quiet, mid-range bands"* (`:821`) |
| Value inputs (`:142`,`:145`) | `type=number`; write `edV1` / `edV2` as raw strings (`:825`) |
| Search box (`:152`) | Case-insensitive `includes` filter over `opts` (`:812`) |
| Option row — enum (`:157`) | Radio semantics (`border-radius:50%`): sets `edSel`, single selection (`:831`) |
| Option row — multi (`:157`) | Checkbox semantics (`border-radius:3px`): toggles `edMulti[opt]` (`:831`) |
| `Add` (`:169`) | Appends the **preview string** to `added[screen]`, closes editor and popover (`:835`) |

Option tooltips differ by kind (`:830`): enum → `Currently matching X` / `Match cards in the state: X`;
multi → `Stop including X` / `Include X in the results`.

### 5.5 Chips

Each chip renders its label in mono 12.5px on an accent tint (`:177`). The `✕` remove button is present **only outside
backtest mode**. Removing sets `removed[label] = true` (`:730`) — keyed by **label text, not by screen** — and the
removal is wiped whenever a screen is picked (`:711`) or a new screen is created (`:854`).

### 5.6 Results band

| Control | Consequence |
|---|---|
| `terminal` (`:187`) | `view='terminal'`; tooltip *"Terminal density — more rows, tighter type, every metric column"* |
| `binder` (`:188`) | `view='binder'`; tooltip *"Binder density — fewer rows with card art"* |
| `Save` (`:191`) | `saved=true` for 1800 ms then reverts; label/colours swap to `✓ Saved` green (`:857–860`). No persistence occurs |
| `Backtest →` (`:192`) | `bt=true`, `btPhase='idle'`. Carries the long educational tooltip verbatim at `:192` |
| `← Results` (`:195`) | `bt=false` |

### 5.7 Terminal table

Column header click sorts (`:781`); repeat click on the same key flips direction; a new key starts descending.

### 6.2 Chip grammar — generated, never authored (`:796–809`)

```
range  →  {short}[ {window}] {op} {value}          op ∈ {≥, ≤}
range  →  {short}[ {window}] {v1}–{v2}             op = between   (no literal word "between")
enum   →  {short}: {selectedOption}
multi  →  {short}: any                              0 selected
multi  →  {short}: {a}, {b}                         1–2 selected
multi  →  {short}: {N} selected                     3+ selected
```

Value formatting (`fv`, `:796–804`):
- empty/null → `…`
- `signed` metric with value ≥ 0 → leading `+`
- unit `$` → `[−][+]$1,234` (thousands grouped, sign outside the `$`)
- unit `×` → `×1.4`
- any other unit → value then unit (`5%`, `90th`, `+1.5σ`, `6 mo`)
- no unit → bare number (`0.6`, `30`)

The preview string shown at `:168` *is* the chip text that `Add` commits (`:835`) — one string, no structured record.

### 6.3 Filter semantics

- Filters **AND** together; the `+ filter` tooltip states it: *"Add another condition — results must satisfy every
  filter"* (`:99`). There is no OR, no grouping, no negation anywhere in the prototype.
- Cautions are informational and never block `Add` (`:164–169`).
- **In the prototype, chips do not filter.** `rows` is `CARDS` sorted, never filtered (`:738–744`), and `matchLabel` is
  always `rows.length` = 12 (`:856`). Chip state, hidden-count, and match count are decoupled seeds.

### 6.4 Terminal / binder parity

Both views render the **same** `sorted` array (`:744`, `:838`), so sort order carries across the toggle. Binder drops
every column except name / price / ROC 3M, drops the state badge, the hidden-rows banner, and the hover preview.

### 6.5 Backtest invariants

- **Entry rule is fixed and not editable**: `card enters “{screen name}”` (`:207`, `:603`). There is no entry-rule control.
- Filters are read-only in backtest mode: `+ filter` is hidden and chip `✕` is suppressed (`:97`, `:177`), with the
  explicit label "filters are read-only while backtesting" (`:198`).
- The dataset is chosen by screen id: `g1`→short, `g2`→short, `g3`→mid, **everything else**→long (`:521`, `:586`).
  Date range, honest floor, equity curve, and entry count are properties of the **dataset**, not of the horizon or exit
  mode — switching horizon or exit mode never changes the curve or the range.
- `Max drawdown` always reads `stats['3M'].dd` regardless of the selected horizon (`:640`) ⇒ **every dataset must define
  `stats['3M']`** or the render throws.
- Equity y-scale spans `min/max` over both series concatenated; the dashed baseline sits at value 100; the `100` axis
  label is suppressed when it would land within 10%/12% of the plot edges (`:578`).
- Histogram buckets are fixed at 6: `≤−10%` · `−10–0` · `0–10` · `10–25` · `25–50` · `50%+` (`:598`); the first two are
  negative-tinted, the rest positive (`:661`); bar height = `round(n/max × 92) + (n>0 ? 4 : 1)` so a zero bar still
  shows a 1px stub.
- Entries table always shows **all three** horizon columns in horizon mode; the selected one is tinted (`accBg`) in both
  header and cells and set to weight 700 (`:665–666`, `:674`).
- Standing disclosure under the table: *"Returns are gross of selling fees. Each entry snapshot is computed only from
  data captured on or before the entry date — lookahead is structurally impossible."* (`:344`)
- Entries (`14`) exceed today's matches (`12`) by design; the `more` line reconciles them:
  *"+ 5 more entries — 12 cards match today; 2 of the 14 entered and later exited the screen"* (`:508`).

## 7. Open questions

- **O-1 — Route collision.** `HANDOFF.md:72` gives the app `/screener`; `HANDOFF.md:84` gives the marketing page
  `/screener` too. `CARDSTOCK_UI_SPEC_v1.md:112–113` omits `/screener/{id}` entirely. The HTML settles nothing.
- **O-2 — Is backtest a route or a mode?** The prototype implements it as a state flag with no URL. If
  `/screener/{id}/backtest` is a real route, entering it must reset `btPhase` to `idle` (`:601`) and leaving must
  preserve `btH`/`btExit` to match the prototype.
- **O-3 — Chip identity.** A chip is a bare string (`:835`). Removal is keyed on that string globally (`:730`), so two
  screens with an identical chip label share removal state, and a saved screen cannot round-trip into a structured
  query. The real implementation needs `{metric, window, op, v1, v2, selection}` with the label derived — decide before
  persistence is designed.
- **O-4 — Gem rate preview duplicates its own short name.** `short:'Gem rate'` with `windows:['Gem rate','Drift 90d']`
  produces the chip `Gem rate Gem rate ≥ 40%` (`:553`, `:807`). Intended text unknown.
- **O-5 — Deleting the last screen.** `del` falls back to `rest[0]`, which is `undefined` when the list empties
  (`:726`), and `SCREENS[undefined]` would throw at `:692`. No empty-rail state exists in the prototype.
- **O-6 — `sub` is never recomputed.** `"4 filters · edited 2d ago"` is seeded text (`:462`); adding or removing chips
  does not update it, and `Duplicate` copies the source's sub verbatim (`:723`). Needs a real derivation rule.
- **O-7 — `Duplicate` loses user-added chips.** It copies `SCREENS[id].chips`, not `added[id]` (`:721–724`).
- **O-8 — `show anyway →` is inert.** It flips `revealHidden`, which nothing reads (`:873`). The reveal presentation
  ("metrics marked unreliable") is unspecified in the HTML.
- **O-9 — `export CSV ↓` has no handler** (`:322`); the tooltip is the only specification of the payload.
- **O-10 — Terminal rows are `role="button" tabindex="0"` with no handler** (`:360`). The spec's row-click → peek-panel
  behaviour (`CARDSTOCK_UI_SPEC_v1.md:87`) is not implemented here; binder tiles are the same (`:393`).
- **O-11 — `hiddenCount` / `hiddenMetric` are constants** (`:872`) and the churn column tooltip hard-codes
  "3 cards hidden" (`:773`). Real values must come from the sufficiency engine.
- **O-12 — The declared `defaultView` prop is never read.** It is declared as an enum prop with default `terminal`
  (`:417`), but `state.view` is initialised to the literal `'terminal'` (`:427`). Decide whether view mode is a
  per-user preference, a per-screen property, or neither.
- **O-13 — Empty / loading / error states are absent.** There is no zero-match state, no skeleton, and no error state
  anywhere on this screen; `CARDSTOCK_UI_SPEC_v1.md:429` proposes no-results copy that the prototype never renders.
- **O-14 — Composite G3.** Charts carries four composites (G1–G4, `DISPLAY_VOCABULARY.md:170–173`); the Screener menu
  offers only G1, G2, G4 (`:499–500`). Whether G3 (Breakout Confirmation) is deliberately un-screenable is unrecorded.
- **O-15 — Save has no persistence semantics.** `doSave` is a 1.8 s visual confirm (`:860`). What Save writes — chips,
  name, thesis, view mode, sort — is undefined.
- **O-16 — Every date, ratio, and coverage figure in the caution copy is known-wrong** per D-001 / D-031 / D-032 /
  D-033. See §8; these strings must be regenerated from the 2026-09-01 floor rather than transcribed.
