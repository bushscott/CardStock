## Screener decisions (2026-08-03)
- Header layout: title+thesis row → filter row (+ filter FIRST so popover never drifts off-screen, then chips, right-aligned "N matches"). Actions live on the RESULTS band, not the header: terminal/binder top-left; Save/Backtest→/Alert me top-right. User rejected thesis-next-to-buttons variant.
- + filter popover: two-level (signal list with group headers + data badges → per-signal editor). Editor shapes: range (window pills + ≥/≤/between + unit inputs $/%/×/σ/th/mo), enum (radio), multi (checkbox, search on Set/Character). LOW DATA cautions repeat inside editors. Chip preview + Add appends to active screen. Click-outside dismisses (guard: e.target.isConnected — re-render race ate menu clicks).
- Save button plays ✓ Saved green confirm (~1.8s), same treatment as watchlist.
- Backtest = a MODE of a saved screen (spec §4.5), not a page: swaps results area; rail+header stay; filters read-only w/ BACKTEST MODE badge; ← Results returns.
- Backtest config: entry rule (fixed "card enters screen") · exit rule toggle **horizon exit / signal exit** (lowercase mono = mode-toggle tier; plain-English "timer vs cook-until-done" explanations live in hover tooltips, NOT labels — user rejected long labels) · Sell after (horizon) 3M/6M/12M pills (stay visible but dimmed+inert in signal-exit mode so Run doesn't jump) · date range.
- Jargon convention: plain words + jargon in parentheses — "Sell after (horizon)", "Buy signals (entries)", "This screen's history starts X (the honest floor)". Finance-literate but self-teaching.
- Results anatomy: plain-English story line FIRST (blue tint: "We found N buy signals… X% made money… vs index"), equity curve vs index (y-axis gutter 32px left of plot, crosshair hover w/ month+both values, x labels start/mid/end, 100-baseline label hides when it'd collide), stat tiles 3×2 grid sharing a row with histogram (460px col), tiles have title-attr tooltips + cursor:help, entries table full-width.
- Stat tiles: Buy signals (entries) · Hit rate · Median · Mean · Max drawdown · Market index (same-window buy&hold — "the bar to beat") + Best/Worst entry (blowup risk). Exit mode swaps to: Hit rate (closed trades) · Median return · Median hold · Open positions.
- Entries table: ALL THREE horizon columns (+3M/+6M/+12M) always shown; selected horizon highlighted (tint+bold). User initially had me collapse to one column, then reversed — context columns are valuable, highlighting connects toggle. Same table rules as rest of app (resize pipes, centered). Exit mode: Exit return/Held/Status cols, OPEN·unrealized rows.
- Honesty patterns: honest-floor callout always visible w/ reason; unmeasurable horizons DISABLED w/ maturity-date tooltip (never dash-only results); entries ≥ today's matches (14 vs 12, footer reconciles); concentration warning (red) when >50% of signals from one set; loading line shows window AND horizon.
- Educational insight from user testing: window vs horizon vs matches vs entries confused a smart user for ~20 turns. Every backtest concept needs its plain-English sentence within hover distance. "The screen is a question, not a list" and "timer vs thermostat" were the explanations that landed.
- BACKTEST_WARNINGS.md: 15 warning checks for the real engine (3 in prototype), severity-tiered red/amber/grey. Delivered as download. Candidate to add: whipsaw/re-entry flag (signal exit is twitchy — one filter failing = sell).

## Card page decisions (2026-08-04)
- Tier strip runs PSA 10 first (descending grade); right column spreads to fill art height.
- Card art click-to-enlarge lightbox (zoom-in cursor; ✕ top-right, backdrop click closes).
- Listed column DROPPED from sales ledger — production coverage is 4.4% (143,062 of 3,265,910 sales). Where a listed price exists, the Realized cell gets a dotted amber underline + tooltip "listed $X → sold $Y". A 95.6%-blank column reads as broken, not sparse.
- Sales ledger sortable by any header (click, ▾/▴, desc first; grade sorts by rank, ties fall to date). Seam markers only render in date sort — they're chronological annotations.
- Missed-sales scraper alert removed (user: capture is complete).
- **Current-month point methodology**: the month-to-date point is computed with the SAME aggregation as closed months (median of the tier's sales captured since month start, outlier-trimmed), just on partial data — recomputed as each sale lands, frozen when the month closes. NO projection/extrapolation to month-end, ever (violates honesty stance; daily/weekly resolutions are the honest "right now" view). Presentation: final chart segment dashed + hollow end dot with tooltip, no text warning. Same treatment to be applied in Charts.

- **Summary-line templates (census + grading activity)**: static grammar, dynamic numbers, defined branches.
  - Gem rate line: rate = trailing 90d PSA subs (min ~30 subs, else omit drift sentence). Drift branches: falling → "harder to gem = supply of fresh 10s slowing" (green); rising → "easier to gem = fresh 10s arriving faster" (red); flat ±0.1pp → "steady" (grey).
  - Pace line: "+N/mo" = latest month delta; rising/steady/slowing = recent 3mo avg vs prior 3mo avg; "+X% in Y months" = new slabs ÷ census at window start. Parenthetical: census growth >2%/mo → "fresh supply working against the price" (red); else → "supply nearly frozen — scarcity intact" (green). Gating: <2 census observations → line degrades to "census history too young to compute pace" (LOW DATA convention).
- Removed from Card page (user decisions): missed-sales scraper alert; seam markers in sales ledger (no seam recognition planned); census restatement hatching (no census-diff detection planned; hatching was my invention, not spec). Footer staleness stamps replaced by "Sales & prices refreshed just now" — card page visits trigger a fresh scrape; census keeps its as-of date (PSA/CGC publish on their own schedule).
- Price preview chart: all 6 tiers as clickable legend toggles (PSA 10/9.5/9/8/7/Ungraded; 9.5/8/7 default-hidden), y-axis rescales to visible, ≥1 series always on, hover readout follows visibility. "full playground →" renamed "open in Charts →" (no new vocabulary).

Card-header chips: firing-only, cap 4, priority composites→RS→supply→momentum→liquidity; watchlist chips: tracked, all states shown. Keep in sync when adding elements.

## Browse + Set decisions (2026-08-04)
- **Pokédex data model note (user ruling)**: card ↔ Pokémon is MANY-TO-MANY, not 1:1 — some cards picture multiple Pokémon (tag teams, duo cards, etc.). `card_characters` must be a join table (card_id, species), and species aggregates (printings count, total market value) count each card once per featured species. A multi-Pokémon card appears under every species it features.
- **Pokédex source data (user ruling 2026-08-06)**: the app relies on an EXISTING, already-populated Pokédex-type schema — species records with name, generation, region, type(s), evolution line, status. Cardstock does not author or maintain this data; it joins to it. Species-level filters/facets may assume those fields are present and complete, so no METADATA PENDING honesty state is needed on Pokédex attributes (unlike card/set metadata, which can be missing — spec §4.8).

By set = era shelves (WOTC / Sun & Moon / Sword & Shield + "Uncategorized" shelf w/ METADATA PENDING badge — honesty state from spec §4.8). Set tiles: 3-card fan (accent gradients, front card is an image-slot), name, count, 30d %. Only Evolving Skies links to a built Set page; others tooltip why. By pokémon = species grid ordered by total market value (accent initial circle, printings/sets, total value, 90d %) + filter box; character pages are P2 (#).
- **Cardstock Set.dc.html** (Evolving Skies): dominant-accent bar under nav (Umbreon dark blues), header (name, SWSH07 chip, era/release/count, 12M set-index sparkline, 30/90d %), terminal ⇄ binder toggle, sort pills (value/ROC 3M/RS/pop Δ).
